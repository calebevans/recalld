# Public similarity selection, metadata and exposure

This revision is based only on scoped read-only PR37 `89e0cf3`, explicit-vector PR28 `f022127`, and online effects PR39 `cdee36e`, plus their existing ancestors. PR17 is not needed: this path uses existing canonical point/batch reads and the pre-PR17 three-argument vector-index API. It does not import the combined aeab9e6 validation ancestry, namespace batching, compaction, entities, removal ledger, schema migration, transactional observation, or evaluation branches. Original runtime `c9e7d3d`, evidence `b2dad0f`, and frozen aeab9e6 remain unchanged.

The parent join preserves scope/access arguments, supplied vectors, injected clocks, guarded lifecycle transitions, effects-backed Ghost deletion, derived completion handles, and fail-closed read admission. Tests inherited from PR39 use the combined scope/access signatures and a valid source embedding. The former HTTP-similarity-error assertion now requires the success enabled by PR28.

`minScore` means minimum cosine similarity in single-memory similarity; `/search minStrength` remains a distinct strength filter. REST and MCP share canonical source scope, vector validation, source/score/limit selection, canonical visible result metadata and actual namespace names. REST uses cosine order rather than its old general-search ranking path.

REST hydrates every selected result from its actual canonical record with `MemoryResponse::from_cached`, preserving difficulty, raw strength, decay strength and all other metadata. Optional embeddings and full text remain supported. Full-text read errors propagate, and admission is rechecked before exposure. It no longer constructs difficulty as 5.0 or treats a search projection as canonical response metadata.

The shared `record_similar_accesses(&[MemoryId])` hook deduplicates IDs and awaits the existing associative batch recorder. MCP invokes it after selection; REST queries with recording deferred, hydrates every response, then invokes it once. Empty results and failed hydration cause no exposure. This hook is coordinated with the separate transactional-observation consumer owner and is not a second recorder.

Regressions exercise both production handlers, nondefault namespaces, low-strength/high-similarity records, independent search strength filtering, false and empty modes, default/explicit true mode, limit exclusion and exact canonical history increments. The REST metadata case uses difficulty 7.25, strength 0.23, decay strength 0.67, a stale cache, real full text and requested embeddings; it compares the entire serialized memory against the canonical response helper. A corrupt text reference must fail in false and true modes with unchanged state/events.

This is legacy-v1 repair, not A1/A3 receipt completion. The existing batch writer is awaited but not receipt-atomic: partial failures and read/exposure races still require the separately coordinated transactional path. No canonical barrier/snapshot/reset, frozen clock, lifecycle-v2 serving, API-v2 or all-A6 claim. Hume's later explicit-policy preparation/guard/projection must preserve legacy canonical fields and prevent original true requests from bypassing policy guards through REST's deferred-recording preparation.
