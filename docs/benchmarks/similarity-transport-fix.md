# Public similarity selection and exposure

This child of measured combined runtime `aeab9e68e749e4e178576c2283a6173c11611a31` fixes single-memory similarity across REST and MCP. `minScore` means the minimum cosine similarity, as documented in `docs/mcp.md` and `docs/guide.md` and the REST `FindSimilarRequest` model. `/search` still maps `minStrength` to the strength eligibility filter. These meanings are independent.

Both transports use QueryEngine's similarity selection: canonical source scope, validated source vector, source exclusion, similarity threshold and limit, canonical visible response records, then associative exposure of the final IDs. The shared response resolves the actual namespace, including nondefault by-ID scope. REST no longer invokes ordinary ranked search and then removes its already-observed source. MCP no longer drops score-filtered hits after exposure scheduling. REST optional embeddings and full text remain supported. Similarity now uses cosine ordering consistently rather than REST's previous general-search ranking path.

The real-adapter regression `similarity_threshold_namespace_and_returned_only_exposure` checks both handlers, a nondefault namespace, low-strength/high-similarity results, `/search` strength filtering, false mode, empty true mode, default/explicit true mode, limit exclusion, and exact canonical access-history increments. Source, below-threshold, beyond-limit and foreign records remain byte-identical; returned records receive one associative event without stability growth.

This is a legacy-v1 correction, not A1/A3 receipt completion. The existing AccessRecorder remains asynchronous; failures are logged, not represented by a public receipt. Effects-stamp admission is not an atomic query/exposure transaction. No concurrent-delete/rollback guarantee, full-state barrier, frozen-clock contract, lifecycle-v2 support or API-v2 conformance is claimed. Those require the separately coordinated lifecycle/storage work. Immutable pre-fix evidence and real stdio/HTTP MCP/REST replay results live on the separate evaluation evidence branch, not in the frozen runtime checkout.
