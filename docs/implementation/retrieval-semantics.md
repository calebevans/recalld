# Internal A2 semantics2 slice

Dependent on `impl/retrieval` at `1a63400` (PR #17). This branch provides an explicit Rust-only harness path. **It does not establish a coherent A1 read generation, enable a transport v2 contract, or complete A2.** The research specifications were read, not modified.

## Selection and behavior

`QueryEngine::search(query)` still selects `RetrievalSemantics::V1`. Internal callers may use `search_with_semantics(query, RetrievalSemantics::V2(VersionMode::Current | History))`, receiving `SemanticsResponse { response, diagnostics }`. These selector/diagnostic types have no serde implementation or transport fields. Graph adapters lacking the new bounded read methods return an error rather than claiming a current terminal or empty expansion. Unknown JSON fields cannot opt a normal search into semantics2. `VersionMode` defaults to current; the semantics selector defaults to v1.

- **Current:** canonical origin and terminal eligibility are revalidated; every structural intermediate must have canonical identity in the requested namespace, and the graph node's scope must agree. Missing records/structure, branches, cycles, foreign paths and exhausted budgets omit the origin with aggregate reason counts. Tombstones may carry structural identity between live versions, but never supply scores, seed activation or appear as results. A filtered terminal does not restore the predecessor. Scores merge by `max(own, inherited)` without boosting inheritance again; raw terminal evidence stays separate. Seed evidence also merges by max so discovering a weak terminal independently cannot reduce inherited graph activation.
- **History:** retained eligible versions keep their independent scores, without replacement or inheritance. Returned IDs carry current/historical/unresolved status. This is not an as-of reconstruction or access to erased payloads.
- **Supersession work:** at most 64 successor hops per origin, with a shared 12,800 examined-incoming-edge budget across the query's resolution passes. Boundary inspection proves terminality or detects an overlong chain; it is charged to the query budget even when no further hop is followed. Non-Supersedes incoming edges also consume examined-edge work. Candidate UUID ordering fixes which origins receive remaining work. Incomplete adjacency reads never prove currentness.
- **Graph:** current seeds are resolved before expansion and the expanded union is resolved again afterward. Synchronous UUID-ordered layers enforce depths 0–3, 400 expanded `(UUID, depth)` states and 12,800 examined edges. Directed contributions are deduplicated per source/layer and edge type; seeds are not reinjected. Canonical hard eligibility, live phase and canonical materialized strength govern seeding, receiving and relaying. Ghosts/tombstones never relay, including when ghost metadata is requested. Existing edge factors, fan attenuation, thresholds, hop decay and score formulas are retained. There is no extra union/node cap. If remaining edge work cannot inspect a complete adjacency list, that source contributes nothing and traversal reports incompleteness, avoiding insertion-order-dependent partial results.
- **RIF:** semantics2 never calls the legacy RIF processor. V1 keeps its configured query-local behavior. No persistent RIF, shadow or experimental mode is introduced. The diagnostic `rif_off` means forced off by semantics2; false preserves the v1 configuration rather than asserting that configuration is enabled.
- **Ordering/limits:** finite scores descending, UUID bytes ascending; signed zero is normalized. FTS now includes UUID ordering before its limit. Exact vector scans reject nonfinite scores rather than heap-ordering them. These two correctness checks also apply to v1 without changing its formula weights. Semantics2 metadata candidates use the existing B budget after eligibility and baseline/temporal ranking. Final `totalMatches` counts unique resolved candidates before the result limit, not all corpus matches.

Diagnostics expose aggregate unresolved/work limits, returned-ID version statuses, and minimum contributing graph depths (direct seeds are depth 0). They contain no rejected/foreign IDs or paths. They are an internal subset, not complete v2 coverage/explain envelopes. Existing timing fields are reused: graph expansion is measured in `graphExpansionUs`, and version resolution is included in `rankUs`; no new timing field is added beyond the parent's `eligibilityUs`.

## Integration handoff

- **Read-only recall branch (`impl/read-only-recall`, based on `211b1bd`):** no recordAccess field, cache policy or access-clock changes are made here. Its `if query.record_access` guard must surround the single shared `record_accesses_async` call now inside `search_with_semantics`. Preserve this for both semantics versions. Its legacy `expand_graph_candidates(..., query.record_access)` change remains in the v1 arm; the v2 path already uses canonical metadata directly. Keep canonical batch loading in initial eligibility and legacy replacement validation when resolving the older branch's cache-loading hunks. Its get/similar access wrappers and `StorageAccessRecorder::with_clock` are independent of the graph-reader additions. Query edits here only correct stale filtering comments.
- **Autolink branch (`impl/entity-link-scope`):** `graph/autolink.rs`, entity-index public APIs and writer paths are untouched. Its namespace/normalized-count fix can land independently.
- **Canonical namespace batching (`impl/namespace-read-batch`, based on PR #17):** integrate its `MetadataStore::namespace_records` default/production override and replace the initial `list_namespace_memories`/`get_batch` pair with `namespace_records(ns_config.id)`. Keep the existing eligibility timer around the whole call plus hard filtering/membership construction. Its single-redb-read-transaction implementation improves the namespace read boundary but does not pin graph/vector/FTS views or the separate per-hop resolution reads. This branch leaves those metadata adapter methods unchanged.
- **Evaluator:** the internal selector/response and reason enums are exported from `search`. No additional serde timing fields are required; preserve/consume the parent's additive `eligibilityUs`. Do not label these diagnostics full retrieval-v2 coverage or invent generations.

## Validation and limits

Executed in `recalld-ci:1.94` with Rust 1.94.1, `--network none --cpus 2 --memory 4g`, `CARGO_BUILD_JOBS=2`, and dedicated cargo/target scratch directories. No host home, credentials, daemon socket or personal data mounts.

- `cargo test --locked --offline --all-targets --features bench --quiet`: **528 passed**, zero failed (19 added tests); both binary targets compiled with zero tests.
- Rustfmt checks passed for every changed Rust file.
- `cargo clippy --locked --offline --all-targets --features bench` completed with repository warnings; no warnings-as-errors clean claim.

Tests use synthetic records, actual graph/vector/entity adapters, and a real storage/RIF fixture. The RIF fixture deliberately uses a no-op exposure recorder to isolate query-local suppression from the separately owned default access mutation; it does not prove production `recordAccess=false` conformance.

Coverage includes 0/1/64/65-hop chains; cycles, branching, missing structure/records, canonical versus cached graph scope; every terminal hard-filter category; same-scope tombstone intermediates; weaker/stronger own evidence, minScore and temporal inheritance; dense shared supersession/graph work limits; exact graph distances, diamond/cyclic paths, filtered relays, seed replacement and graph-result replacement; metadata/FTS tie boundaries; nonfinite inputs/sources; and real legacy RIF score differences without persisting suppression. A real tombstone mutation between queries changes the next query's eligibility.

A1 must still supply coherent canonical/graph/index views, publication readiness and generation barriers. Separate reads here cannot rule out concurrent changes between enumeration, path steps and expansion. Namespace-index integrity/rebuild and mutation-side cycle/branch rejection remain prerequisites. Do not expose transport v2 on this implementation alone.

Also remaining: stable eligible FTS refill and explicit degraded-channel handling; complete channel coverage/provenance/explanations; namespace-partitioned entity publication; lifecycle-clock/strength policy integration; synchronous observation receipts and production read-only conformance; transport versioning; and A5/A6 full-pipeline latency/RSS, quality and replay gates. Per-hop canonical reads and bounded graph work have not established a performance gate. No ranking/RIF experiment or default lifecycle promotion is authorized by these tests.

A5’s 2026-11-14 paired characterization of parent PR #17 found substantial namespace-loading overhead (median process-p95 ratios about 1.24x/1.22x at 1k and 2.85x at 10k; eligibility accounted for 67–70% of engine time at 10k). This diagnostic shared-host study is not a formal release-gate test. Correctness remains required, performance promotion remains unapproved, and the canonical batch-read optimization needs its own paired remeasurement. This semantics2 branch has no performance promotion claim.


## Reciprocal-edge rebuild correction

Follow-up on `35291e0`: normal graph insertion rejects same-type reciprocal edges, but startup rebuild loads stored `A -> B` and `B -> A` independently. The prior `(neighbor, type)` deduplication discarded one direction while fan attenuation and examination counts included both. For weights 0.01/0.8 and canonical strengths 0.9, depth-one expansion incorrectly omitted B instead of producing activation about 0.4435503.

Deduplication now uses the stored directed `(source UUID, target UUID, type)` identity, matching the persistent edge key. Neighbor UUID/type order is retained, with source/target UUIDs breaking reciprocal ties. Every inspected adjacency still consumes examination work before deduplication; existing fan attenuation, thresholds, layer limits and seed handling are unchanged. This is a semantics2 correctness fix, not a change to legacy activation or graph mutation.

Two regressions load actual persisted-edge fixtures through `rebuild_from_storage`: both insertion orders match the directed-edge oracle and return B through the engine; equal-activation reciprocal neighbors retain UUID ordering, duplicate seeds do not reinject, and all directed adjacency examinations are counted. The all-target suite also retains the existing 400-state and 12,800-edge ceiling tests. Validation uses the same isolated offline Rust 1.94.1 container settings above. This focused fix is based directly on `35291e0`; apply it to the semantics PR before updating FTS/diagnostics children.
