# Retained-state logical export and import

`storage::logical_export::export_store(source, file)` and `import_store(file, destination)` are offline operations over the existing backend. Both return `ExportSummary { exportId, source: GenerationRef, chunks, records, logicalSha256 }`. A4 owns their operator CLI consumer. Source schema must already be v2: use the explicit schema migration for v1; no decoder invents migration time, profile provenance or policy activation. Ordinary v2 serving remains disabled.

Export acquires a validated `OfflineSnapshot` and publishes a fresh file outside the source with synced no-clobber persistence. It never writes the source. Export format 1 is a strict JSON-lines stream: header, monotonically sequenced checksummed chunks, then a mandatory footer. Header identifies export UUID, canonical schema 2 and source lineage/generation. Each chunk contains one namespace, canonical table declaration/row, logical memory or edge. Lines are bounded to 16 MiB, including JSON escaping; oversized canonical values fail rather than producing an unimportable artifact. Unknown required versions, relation names, table kinds, malformed/truncated/trailing data and duplicate/unordered identities fail closed.

Logical memories use the checked record codec with physical text offsets and vector slots normalized to zero, plus retained text and exact embedding f32 bit patterns. Record/lifecycle/edge floats never pass through an approximate SQL numeric conversion. Exact structured-label order, duplicates, case and optional record extensions survive. Unknown profile identity stays unknown; immutable bound identity/provenance remains exact. Receipts, retry keys, namespace counters, removal ledger and coverage, applied effects, and restore ancestry are explicit typed relations. Shared integrated validation remains responsible for all their required versions and cross-table invariants. Standalone builds reject unsupported control/receipt variants; they do not guess future formats.

Only canonically reachable payloads enter the stream. Database pages, free slots, unreferenced text extents, obsolete files and cached/derived artifacts do not. Stripped canonical fields are never reconstructed from old log bytes. Tombstones cannot export content or embeddings. Retained legacy Ghost tags are preserved according to their existing semantics. Checksums and hashes provide damage/fidelity detection, not archive authenticity or forensic erasure of retained source files/backups.

The transport checksum chains every chunk from the header. A separate deterministic logical SHA-256 includes source identity and every sorted logical relation/row/payload. It excludes physical text catalog entries and relocated offsets/slots; catalog history is still transported and checksummed. New export UUIDs and generated text filenames do not change logical identity. Import compares the complete reconstructed logical hash and record count before publication, not a sample of records.

Import first validates the entire bounded stream. It creates a private sibling stage identified by destination plus export UUID. A durable `.recalld-importing` marker denies ordinary inspection, export and backup of incomplete stages; only the private importer validation path may inspect that unpublished stage. Checkpoint state in `logical_import_progress` binds the export identity, complete-stream checksum, last committed sequence and prefix hash. Matching retries resume committed chunks; a different export/checksum cannot adopt the stage.

Payload append/sync precedes each record-plus-checkpoint transaction. Edge rows are idempotently materialized before their metadata checkpoint. A crash can leave unreachable copies of retained payload within staging; it cannot publish partial canonical state or duplicate logical records. The importer builds fresh vector/text payload files, tag/namespace indexes and edge reverse entries, retains physical descriptor history, and selects its new sealed text generation in metadata without changing lineage or generation. It then validates complete canonical state, recomputes logical fidelity, marks progress validated, syncs files/directories and renames into a fresh destination. A matching completed-import retry validates and returns the existing result; other existing destinations are refused. No serving replacement or restore lineage fork occurs here, and no cross-file atomicity is claimed.

Unapplied canonical effects are rejected before export. Applied effects awaiting derived acknowledgement are retained byte-for-byte with their original receipts. Production restore owns either ancestry-aware validation or validated consumption of completed derived work; it must not rebind historical receipts or infer ancestry. Pascal's separate schema/restore bridge `ad64089` implements validated consumption of applied rows after private persisted rebuild inside the fork transaction, retaining original receipt/key bytes and immutable schema source/publication evidence. That bridge is an integration prerequisite, not ancestry pulled into this branch. Logical import does not authorize serving, rebuild FTS/provider-dependent indexes, or claim derived readiness. Operator cutover and complete participating writers remain required.

Tests use synthetic temporary stores and offline, resource-limited Rust 1.94.1 Docker. Coverage includes real retained/deleted payloads, exact float bits/Unicode/profile/receipt round trips, source immutability, valid-checksum future-schema rejection, unknown canonical tables, bounded malformed streams, and process exits at initialization, chunk commit, payload sync, edge commit, selection, validation and publication. These are process-interruption checks, not arbitrary power-loss or all filesystem-failure guarantees.

Import also checks available destination-filesystem space before creating or resuming a stage. The conservative estimate includes twice the stream size, 8 KiB per chunk, each namespace's possible vector growth slack, and 64 MiB database headroom. Existing retained source/export/old-store bytes remain in place and already reduce available space. A completed matching import retry needs no staging allocation. This is a capacity precheck, not a reservation or exact write-amplification guarantee; later disk-full/I/O errors still leave only private staging and no successful publication. The deterministic zero-space probe verifies no stage/source mutation and a successful later retry. Production restore capacity accounting remains owned by its separate publication path.
