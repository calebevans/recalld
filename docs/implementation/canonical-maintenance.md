Parent: validated tombstone `1ae3d5a` (published `dad8465` adds evidence only), including corrected insertion `7fa19f8`. This slice retains existing FSRS formulas, defaults, sampled clocks, phase order and temporary RIF behavior. Native schema-v2 serving stays gated.

`RedbStorageEngine::apply_legacy_decay_with_receipt(&self, ctx, id, expected, namespace, phase, strength, decay_strength)` returns `DecayMutationResult::Committed(WriteReceipt)` or `Skipped(DecaySkip::{Unchanged, Stale, Exempt})`. Skips neither advance generation nor reserve a receipt. The ordinary engine `apply_legacy_decay` delegates to this path, and the real sweep consumes its typed result. HTTP sweep results and background logs report separate stale/unchanged/exempt counts.

The shared private `RecordMutation::LifecyclePatched { before, after }` transaction tail writes the patched record, payload-free `LifecycleMaterialized` outcome, receipt, loss ledger and derived-work entry together. The outcome contains identity, before/after phase, numerical strength bits and removed-field mask. Mask calculation is shared with `removal_ledger::record_change`; its operation/generation match the receipt. Legacy Full→Summary removes full-text references; Summary→Ghost removes summary, preserving tags and vector ownership. The existing hard-delete path alone removes that vector and retains its live-owner release validation. No physical-erasure or cross-file atomicity claim is made.

The existing final canonical-record/policy/graph rechecks remain in place under graph→storage locks. Reprojection uses the originally sampled clock, not a later wall clock. The shared staging helper patches a freshly read record and never copies an old record over concurrent feedback/content loss. Same-phase strength equality is compared by encoded bytes; stale and exempt outcomes are distinct. Matching replay precedes CAS/current-record checks and preserves the original receipt.

Effects apply canonically before ordinary admission resumes. Derived completion runs after graph/storage guards are released. Manual and background sweep consumers await the existing completion worker; failures retain durable work and a real committed receipt. The HTTP handler preserves that typed error as 503/`INDEX_NOT_READY` instead of flattening it into an internal error. Canonical-application failures retain their original receipt (or uncertain operation ID) before later unavailable-handle errors can mask it; known canonical transitions still contribute to transition counts. Unchanged canonical strength may repair the graph projection without another receipt/generation. A raw `execute_sweep_at` result describes the canonical sweep only and is not a readiness/barrier proof.
