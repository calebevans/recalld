# Canonical schema-v2 codec and migration work

This slice adds codecs and offline fresh-destination migration without enabling ordinary schema-v2 serving or activating lifecycle v2. `DiskRecord::CURRENT_VERSION` remains 1 for existing adapters. Legacy insertion rejects v2 records before payload allocation; consumers need an explicit participating-writer path. Logical export/import, backup manifest v2, removal-ledger/effects integration, restore-lineage and complete writer/readiness integration remain required.

## Stable consumer interfaces

`model::schema` owns `RecordSchemaV2`, `NamespaceSchemaV2`, `LifecycleFields`, `LifecycleVersion`, `TimestampOrigin`, `StructuredLabels`, `LabelProvenance`, `EmbeddingProfile`, `PreprocessingIdentity`, `ProviderKind`, `Normalization`, `EmbeddingBinding`, `BindingProvenance`, and `VectorReference`.

`DiskRecord.schema: Option<RecordSchemaV2>` and `NamespaceConfig.schema: Option<NamespaceSchemaV2>` preserve v1 defaults when absent. The v2 record layout is byte 2, u32-LE length + complete v1 base bytes, then u32-LE length + schema JSON. Binary base floats retain their exact f32 bits. `DiskRecord::encode()` checks the version/schema agreement and schema invariants; canonical persistence uses it. `from_bytes` rejects truncated/trailing records, invalid retained tags and unknown event kinds instead of silently dropping tags or inventing retrieval events. Namespace decode rejects unknown required fields/versions. Optional `extensions` maps round-trip; nonempty unknown `requiredFeatures` blocks decode.

A3 fields use their normative names: observed/retrieved/reinforced times, decay anchor, lifecycle version/update time, timestamp origin, phase-change time, policy revision and record generation. Revisions use the shared decimal-string u63 representation. Legacy conversion takes one explicit `migration_now`; it does not read wall time. Observed time uses creation with `legacy_inferred` provenance, anchor preserves old last access, lifecycle update is max(created,last access), and phase-change time records migration time when history is unknown. Retrieval/feedback dates come only from matching retained typed events; missing history stays unknown. Native and migrated namespace defaults remain `legacy_access_v1`.

Labels are exact ordered UTF-8 strings, including duplicates, spaces, apostrophes and case. They are separate from Tag encoding. Legacy conversion preserves original tags and copies only raw retained entity/topic/emotion suffixes; `LegacyRetainedOnly` records that previously dropped labels are unrecoverable. Ghost/tombstone conversion adds no structured content. Derived normalization and consumer indexing remain separate.

## Embedding identity

A binding is `UnknownLegacy` or `Bound { profile_id, descriptor, provenance }`. Known binding provenance distinguishes native-v2 creation, explicit operator attestation and re-embedding. Migration must not infer identity from dimensions/current configuration or normalize old vector bytes. `VectorReference` stores slot, initialized allocation epoch and SHA-256 of exact vector bytes; tombstones have no live vector reference.

Reuse `EmbeddingProfile::profile_id()`, not a second hash implementation. It yields `ep1:<lowercase SHA-256 hex>`. Each field is preceded by its u64 big-endian byte length, in this exact order: `recalld-embedding-profile`, identityVersion as u32-BE, provider kind bytes, exact model ID, one-byte revision-present discriminator, revision bytes only when present, dimension as u32-BE, document preprocessing version, document prefix, query preprocessing version, query prefix, `l2_unit_v1`. None differs from Some(empty). No trimming, case folding, credentials or config paths enter identity.

Supported preprocessing names are `recalld-document-v1` and `recalld-query-v1`; unknown names fail closed. Document-v1 identifies the existing summary + optional two-newline/full-text + optional space/joined merged-tags composition and provider document mode. Query-v1 identifies unchanged query text and provider query mode. Prefix concatenation is literal prefix + text. A composition change requires a new supported version. Unknown model revision remains null.

Codec validation: full offline all-feature suite passed 551 library tests and one CLI integration test, with four ignored doctests. The four added schema tests cover exact Unicode/order/duplicates/extensions and f32 bits, evidence-based legacy timestamps/defaults, malformed/future record rejection, and profile identity distinctions. These tests do not establish migration or ordinary v2 writer conformance yet.

## Offline migration and explicit attestation API

`storage::schema_migration::migrate_schema(source, destination, &MigrationOptions)` requires an existing gated selected-text source, a fresh destination outside it, and `expected_source: GenerationRef`. A legacy text layout first uses `recalld-text-migrate` into a fresh destination. `migration_now: i64` is supplied explicitly once; conversion does not read the clock. `attestations: Vec<ProfileAttestationInput>` defaults to empty. A4 owns the CLI parsing consumer of this API.

The migration holds source/destination ownership and the legacy source lock, validates the source through disposable database copies, and copies the **complete** canonical metadata/edge databases plus required payload files. It converts record/namespace schema in one staged redb transaction, validates and syncs the completed stage, then renames into the fresh destination. There is no cross-file atomic-write claim. Source files remain unchanged. Format-only migration preserves both store ID and generation; an explicit profile attestation advances generation once and writes a payload-free catalog receipt in the same transaction as the binding. All prior receipt/key tables and other canonical tables remain in the copied database. Integrated effects/ledger validators must reject incomplete canonical effects and malformed or missing adopted ledger state before migration; copying opaque bytes is not a substitute for those checks.

`ProfileAttestationInput` is strict camelCase JSON `{namespaceId, namespaceName, descriptor}`. Supplying it asserts that the operator knows **all retained namespace vectors** were produced with this exact descriptor. This is explicit operator provenance, not proof inferred from dimensions, configuration or vector bytes. Migration resolves the canonical namespace, checks both immutable ID and exact name, invokes A4's `prepare_attestation`, and refuses every already-bound namespace, including an identical binding. It checks every owned retained vector for finite elements, nonzero unit norm (f64 squared-norm error at most `1e-5`), and preserves exact bytes without renormalizing. The resulting immutable binding has `OperatorAttestation` provenance. Without an attestation input, `UnknownLegacy` remains unchanged; already-bound profiles copy unchanged when no attestation is requested.

`MigrationReport` contains `state: CanonicalSchemaState` and optional `receipt`. The durable state records schema version 2, migration ID, optional receipt operation ID, supplied migration time, source generation reference and `servingMode: offline`. Receipt is null for format-only conversion. Destination-exists errors never overwrite or retry a published migration. After response loss, `inspect_schema(path)` validates the full canonical store and returns control, schema state, canonical namespaces/bindings and record count for reconciliation. It does not apply effects or open an ordinary serving engine.

Control schema version 2 plus the existing text rejection gate prevent older supported readers from serving the migrated layout. Current engine and direct metadata opens refuse the offline state before a writable canonical database open, using disposable inspection. Read/backup inventory validation checks every namespace/record version, policy relationship, vector slot/hash and bound-vector normalization. Derived indexes are not copied as independent canonical files and no readiness is advertised.

The format conversion preserves legacy policy defaults, f32 record bits, tags, retained text references, vector slots and vectors, lineage and prior canonical tables. Already-v2 records and optional extensions are not rebuilt. Native Unicode label writes, serving writers, profile-aware provider use, feedback-v2 lifecycle transitions and deletion-aware restore remain separate consumers. Previously dropped legacy labels cannot be reconstructed.
