# Internal query strength projection

This slice consumes the canonical schema and offline snapshot (`c9f3314`, including the malformed-attestation fix `41f6974`), retrieval diagnostics (`954eb7e`), and read-only/clock prerequisite (`5177642`). The integration parent is `238619a`. These are actual code dependencies; the research documentation PR is not a parent.

`QueryEngine::with_lifecycle_inputs` receives the instance clock, immutable global decay configuration and global multiplier. `Recalld::with_clock` supplies those inputs in normal configuration assembly without opening the schema-v2 serving gate. Each search resolves its namespace once and samples the clock once. Internal `SemanticsDiagnostics.strength` reports that operation clock, lifecycle version and current namespace policy revision; a physical-v1 namespace has no invented revision. For legacy lifecycle this clock is an operation observation, not a claim that the materialized strengths were recomputed at that time.

`CachedRecord.lifecycle` clones the exact optional canonical lifecycle fields. It does not reconstruct feedback dates, relabel legacy timestamps, infer embedding identity, or change the separate entity-label mapping. Initial enumeration and subsequent graph/version reads require record lifecycle version to match the pinned namespace and record policy revision to be no greater than its current revision. A schema-v2 namespace with missing record lifecycle fields fails closed.

For `explicit_feedback_v2`, the existing A3 `resolve_policy`/`project` functions calculate raw R from `decay_anchor_at`, stability and the pinned clock/policy. The result is local to the operation. Projection precedes vector, FTS and entity eligibility caps and metadata ranking/capping; canonical graph and supersession rereads use the same context. Hard minimum strength uses raw R, while ranking uses effective R. The connection bonus reuses the existing formula, cap and two-hop rule, with canonical same-namespace non-Ghost/non-Tombstone projected raw donor strengths. Query tag filters do not alter those lifecycle donors. Canonical bonus reductions use UUID order. Legacy PQSA has a resolver variant for explicit-policy inputs; retrieval-semantics-2 retains its existing bounded graph traversal. Legacy-policy callers retain materialized strength and baseline ranking/RIF formulas under either retrieval semantics.

Explicit-policy search requires `recordAccess=false` under either retrieval semantics. True mode fails before invoking the legacy exposure recorder. Direct-fetch and similarity helpers remain unsupported for explicit-policy records, including false mode, until they can resolve and project the same pinned policy; canonical checks precede any cache/access path. No policy toggle, feedback/exposure writer, receipt, retained-phase change or materialization is introduced.

`OfflineSnapshot` implements the query metadata and namespace interfaces in `search/adapters.rs`. Its source ownership and validated canonical copies provide the sanctioned offline path; ordinary storage open still rejects the offline schema-v2 store. The offline adapter uses a complete scan and canonical payload reader, not a serving-performance implementation. Tests alone change policy fields in a closed, migrated temporary store, using the schema owner's approved coherent fixture procedure, then reopen through strict `OfflineSnapshot` validation. Synthetic query embeddings/indexes in this fixture do not attest an unknown legacy embedding profile or certify serving readiness.

Validation runs with Rust 1.94.1 in `recalld-ci:1.94`, `--network none --cpus 2 --memory 4g`, two Cargo build jobs, and private cargo/target directories. Ten new real-engine regressions cover canonical byte preservation, retained Summary/permastore and unknown timestamp provenance, clock advancement, namespace/global multiplier resolution and revision pinning, legacy parity, projected eligibility before all candidate caps, raw-vs-effective thresholds, canonical donor scope/phase, fail-closed exposure/helpers, invalid replacement revalidation, returned graph-result projection, and the legacy retrieval graph formula with explicit-policy inputs. Final validation: `cargo test --locked --offline --all-targets --features bench` passed 637 library tests plus one CLI integration test (638 total, zero failures); `cargo fmt --all -- --check` passed; all-target Clippy passed with warnings (319 library / 328 library-test / one binary warning, including two new uses of the existing large-StorageError callback signature). Logs remain untracked under `.validation/`.

Remaining prerequisites: A1 generation-pinned serving views and all-writer participation/readiness; production lifecycle migration, feedback and exposure writers; direct/batch/similar projection and transport envelopes; full structured-label/profile consumers; legacy diagnostic projections and any additional A3 phase-preview fields; operator RIF modes; and A5/A6 combined correctness/performance gates. No full-v2, coherence, serving activation, or performance-promotion claim is made. Projection/enumeration cost is included in existing `eligibility_us`; no timing field is added. When integrating the separate namespace-batch optimization, keep its `namespace_records` call and project the returned canonical records before filtering.
