# Canonical writer restrictions

Minimal runtime prerequisites are maintenance d2e83b3 and namespace purge f6e4d92. The final write transaction shares namespace_state::require_namespace_active for insertion, tombstone, lifecycle patch and catalog policy. Catalog creation checks the same durable global purge state; ordinary record/edge effect completion checks it too. Only the existing private purge chunk path bypasses that state to finish deletion. Missing or changed lifecycle policy still reports stale separately from an exact no-op.

The production Rust StorageEngine trait no longer exposes fixture-only raw insertion, tombstone, phase/strength replacement, content stripping, generic batch decay, edge-count overwrite or vector-slot release. Existing unit fixtures retain these under cfg(test). External callers must use canonical insertion/tombstone/maintenance and graph-effect writers plus awaited derived publication. Backend writable constructors and mutations are storage-internal; public engine accessors no longer expose those implementation handles. This is an intentional Rust API break.

The actual benchmark ingestion caller uses existing DerivedCompletion insertion with its explicit timestamp, configured initial stability and optional supersedes edge. It no longer creates a raw record then independently patches canonical links. No public benchmark-loader escape or alternate engine is added. The benchmark still has its existing post-creation link flow and must participate in Halley's accepted-work accounting before any barrier guarantee.

Feedback remains a real consumer dependency on Observed58: it must reuse the shared receipt implementation when joined, without creating another feedback writer. Native-v2 serving remains gated. Purge offline export/restore compatibility and ancestry-aware progress merging are a separate required child. These restrictions do not claim a complete all-writer barrier or certify effects_epoch as a canonical generation.
