# Offline measurement foundation

This is an independently runnable A5/A6 **slice**, on the existing legacy
implementation. It does not implement the integrated A6 public-action harness,
contract v2, lifecycle replay, a performance promotion gate, or semantic quality
evaluation. It changes no production storage/search/daemon code. Existing LoCoMo
results remain a separate legacy evaluation track.

Run from this checkout with the locally prepared Rust 1.94 image:

```sh
python3 scripts/offline-evaluation.py \
  --cache /tmp/recalld-unit-tests-l__ja1yo/cargo
```

The runner copies source and the scratch Cargo registry into a new temporary
directory, with independent cargo/target directories. It runs formatting checks,
library tests, harness tests, Clippy, and a release build, then three separate processes
with seed 7, 1,000 records, d384, k20, 20 warmups and 100 measured queries per cell.
Every Docker execution uses `--network none`, 2 CPUs, 4 GiB, a read-only container
root, a fresh temporary home, and one scratch mount. No home, credentials, socket,
original repository or personal data is mounted. It neither starts nor contacts
a daemon. Missing dependencies fail offline; there is no automatic network fetch.
The default image is `recalld-ci:1.94`, resolved to its immutable image ID before
execution; `RUSTUP_TOOLCHAIN=1.94.1` avoids the repository's `stable` override.

The printed scratch output directory retains failures as well as successes. Do
not commit its Cargo cache, target, fixture vectors, full record dumps or CPU
inventory. Keep compact result summaries and selected raw traces with their
manifest when publishing measurements. The source-tree manifest includes
untracked source files, because a Git commit plus an empty patch alone cannot
identify an uncommitted harness. SHA-256s also cover fixtures, ranks, stored-record
bytes and output artifacts. Container compiler, CPU, memory/cgroup limits, kernel
and mount filesystem are recorded. Filesystem data does not establish host-device
or power-loss durability. There is no provider or external dataset license to
resolve: all inputs are artificial fixture data generated by the checked-in code.

`--records`, `--dimensions`, `--k`, `--warmup`, `--samples`, `--seed` and `--runs`
select a workload. For the earlier exact-index control, use `--k 10` and repeat
at `--records 1000` and `--records 10000`. This runner also ingests those records
into the real storage engine, so larger cells cost more than an index-only probe.
The default is a characterization run, not the A5 release sample plan. That plan
requires five independent seeds (7/19/41/73/101), 200 warmups and 1,000 measured
operations per cell, followed by paired candidate measurements and frozen
absolute budgets. Do not average per-run percentiles or infer sustainable QPS
from inverse kernel latency.

`--build-cache /path/to/recalld-evaluation-previous/target` optionally copies a
prior runner's build output into a separate scratch target; it never shares a
live target directory or lock.

## Measured boundaries

| Cell | Actual code and exclusions |
| --- | --- |
| `exact-index-100pct` | Real `FlatVectorIndex::search`, all records; excludes embedding, storage, query pipeline and transport. |
| `exact-index-10pct` | Same index with namespace prefilter; exactly every tenth vector is eligible. |
| `internal-engine-vector` | Real `QueryEngine::search`, storage namespace/metadata adapters and vector/FTS/entity/cache/graph/RIF adapters. FTS is queried with an absent term, entity inputs and graph depth are empty/zero. |
| `internal-engine-hybrid` | Same engine with an exact fixture keyword hit in the real SQLite FTS index. This is a vector+FTS diagnostic, not realistic semantic search. |

Engine fixtures use direct `StorageEngine::insert_memory` and explicit index
publication. This bypasses public ingestion validation, automatic linking and
transport. Query embeddings are exact-key lookups of precomputed normalized
vectors. Missing inputs fail closed. The only replaced query dependencies are
the embedding registry and access recorder. The latter acknowledges the engine's
asynchronous callbacks without writing, then the harness checks all stored record
bytes are unchanged. This is **not** proof that public `recordAccess=false` works;
that option is absent in this source revision. No A1 barrier or receipt is invented.

The fixture store is on the container's `/tmp` tmpfs. Ingestion timings are a
CPU/logic control, not persistent-disk or fsync performance evidence. The runner
records both the source/output mount and fixture-storage filesystem types.

Stored timestamps are fixed at 2026-01-01 UTC, strength is materialized, RIF is
disabled, graph has no edges, caches start empty and no sweeper is started. There
is no shared injected lifecycle clock or chronological policy experiment. Three
fresh process/store constructions must have identical fixture, record and
rank/score output hashes; this is fixture reconstruction, not A1 snapshot/reset
or crash/reopen conformance. Equal-score production tie semantics are unchanged;
random continuous fixtures are checked against UUID-ordered scalar results and
fail on differing IDs, with a 2e-6 absolute score tolerance. This may flag very
close float ties on different hardware; it must not be silently called a pass.

The raw JSONL retains each measured query's result IDs, timing and response size.
Every existing `StageTimings` field gets count/p50/p95/p99 using the nearest-rank
method. `engineCallUs` measures the awaited engine call; `totalUs` is the engine's
own narrower pipeline timer. `engineAndDiagnosticDrainUs` includes waiting for the
no-write access callback. JSON serialization is timed separately. These are
nested intervals, not additive stage costs, and none is public client latency.
Index oracle computation, scoring and trace writing occur outside timed calls.
Per-stage zeroes can reflect disabled work or integer-microsecond resolution.
Supersession has no dedicated timer. Lock contention, actual scan/load counters,
resource distributions, transport, model latency and sustainable throughput are
explicitly unmeasured; no performance improvement or overhead claim follows.

## Baseline correctness and metric meaning

The exact-index results are compared with a separate scalar f64 exhaustive oracle
at both namespace selectivities. The vector engine is checked against the
eligible oracle with its existing nonnegative-score filter. Both engine cells
must retrieve the self-query source first and return only live records in the
requested namespace. These are deliberately narrow baseline invariants, not the
A2 supersession/eligibility regression matrix.

Evaluator-side mappings record every synthetic source ordinal, UUID and planned
raw-unit transformation. A separate append-only turn ledger records attempted
and accepted ingestion events; failed runs retain partial events and the process
error log. The synthetic query's relevant source never enters the
engine request as a label. Extraction evidence retention is scored against all
accepted source mappings; retrieval Recall@5/10/20, all-required coverage and
binary source nDCG@10 use only retrieved mappings. Duplicate source IDs count
once at first rank. Empty/unknown annotations are unscored, not recall 1. For k
below a metric cutoff, the metric uses the entire available result list; read k
from the manifest. Raw-unit preservation is a baseline, not an extractor-quality
result. Proposition preservation, candidate evidence recall and answer quality
remain unmeasured. Golden tests include perfect, empty, partial, duplicate and
unknown cases, plus deterministic generation and percentile checks.

Manifest and trace keys deliberately use `diagnosticManifestVersion` and
`diagnosticTraceVersion`. They do not claim compliance with the complete A6
`manifestVersion=1`/`traceSchemaVersion=1`, which require unavailable generation,
receipt, clock and provenance interfaces. No paid model, live provider, RL,
backend replacement or production behavior change is involved.
